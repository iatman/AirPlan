# 阅览架实现调研（2026-10-24）

结论：建议采用「文章 front matter 登记 + 可选正文短码 + 构建时汇总」。内容仍写在原周记中，
阅览架负责分类检索与回链；无需数据库、Node、第三方账号或浏览器运行时抓取。
本次仅调研和临时原型验证，没有创建正式阅览架页面，也没有批量改写文章。

## 现有内容情况

扫描了 `content/look/` 中 19 个 Markdown 文件。在其中 15 篇周记的「花」「阅」一级列表中，找到 43 行候选：

- 「花」24 行，包含电影、剧集和动画；有一行同时写《中国奇谭》和《中国奇谭2》，需要拆分。
- 「阅」19 行，其中 5 行是「无」，8 行附 arXiv 地址，另有书和普通博客文章。
- 排除「无」后共 38 条实质候选，并不等于 38 部已核实作品。正文其他章节里的书名引用未全部扫描，故不是完整藏书清单。

候选记录见 [research/shelf-candidates.json](research/shelf-candidates.json)。这些只是待核对数据，不用于正式发布。
例如《超越百岁》出现在周记的「学」和「阅」中；《寂寞的游戏》既有读书感受，也在影视评价里被引用。
不能把所有书名号都当作已读记录，也不能自动把「花」全部归为电影。

## 路线比较

| 方式 | 写作成本 | 优点 | 主要问题 |
| --- | --- | --- | --- |
| 从历史正文提取 | 原文不用改 | 可快速得到初始候选 | 标题、分类、完成状态和重复项不可靠，适合作为一次性迁移工具 |
| 每篇文章的 shelf 元数据 + 可选短码（推荐） | 每条填写 ID、类型、标题；其他可选 | 数据随文章维护，汇总可靠，可回到正文具体段落 | 新增少量结构化标记，重复提及需复用 ID |
| 全站 data/library.yaml 保存作品，文章只记引用 ID | 首次需要改两个文件 | 基本资料集中，适合大量重复提及 | 对目前以周记为主的规模，写作切换成本偏高；可留作后续演进 |

Hugo 官方支持自定义页面参数、数据文件和自定义短码：
[Front matter](https://gohugo.io/content-management/front-matter/)、
[Data sources](https://gohugo.io/content-management/data-sources/)、
[Shortcodes](https://gohugo.io/content-management/shortcodes/)。
官方当前文档的部分目录和 API 已随版本变化，下文遵循本项目 0.110.0 的结构，并通过该版本实际构建验证。

## 推荐写法

在周记 front matter 中增加 shelf 数组。类型建议先用 paper、book、video（影视），普通博客文章可暂不纳入。

```yaml
---
title: 260427 - 第二大脑
date: 2026-04-27T12:00:00+08:00
tags: [weekly]
shelf:
  - id: arxiv-2205-13147
    kind: paper
    title: Matryoshka Representation Learning
    url: https://arxiv.org/abs/2205.13147
    note: 同一个向量，按需使用不同维度。
  - id: film-hyakuemu-2025
    kind: video
    title: 百米。
    year: 2025
    rating: 8
---
```

ID、kind、title 为必要字段；url、year、rating、note、status 均可省略。评分按 0–10 保存，
没有评分就是未评分，不能默认填 0。不根据文章日期推断看完/读完日期，也不默认所有提及都表示已完成。

正文可以继续原有列表格式；如果希望同一份标题、链接自动排版，可在原位置引用元数据：

```go-html-template
{{< shelf "arxiv-2205-13147" >}}
```

短码输出小标题、外链及稳定锚点，后面的长笔记照常写 Markdown。
一句话 note 用于阅览架摘要，长篇评价保留在周记。标题与链接只维护一份。
正式实现应校验 ID 的字符和唯一性；ID 使用小写字母、数字、连字符，可直接对应安全且不易冲突的锚点。

## 汇总与去重规则

- 先处理公开的 Look 页面，读取 `.Params.shelf`，按 ID 聚合作品与提及记录；草稿跟随 Hugo 发布规则。
- 同一作品多篇周记中出现时，保留一张作品卡，附所有来源和各次评价。每张卡按最近一次提及排序。
- 资料有冲突时给出构建提示，不能靠标题近似强行合并。没有 ID 的历史候选，先人工确认再补 ID。
- arXiv 可用论文编号建立 ID，统一 abs/html/pdf 地址并去除版本后缀；书有 ISBN 时可据此标识，影视可用来源 ID 或名字+年份。
- 同名不同版本/改编作品分开记录；是否合并不同译本由人工决定。
- 评分或状态取最近一次明确填写的值，空字段不覆盖历史值；每次评价仍保留在原周记中。
- 正式实现需校验字段、重复 ID、评级范围、回链锚点；错误不能静默丢条目。

## 展示建议

首版提供 /shelf/ 单页，包含论文、书、影视三组，默认按最近提及排列。
每条显示名称、年份（有则显示）、个人评分（有则显示）、一句话笔记，以及原周记的精确回链。
保留与当前站点一致的轻量列表，默认不加载封面；小屏自动纵向排列、长标题换行。
分类可先用原生锚点，无 JavaScript 也能浏览；需要关键词过滤时再加很小的原生脚本。
初期可从归档页进入，避免主导航继续增长。

## 兼容性验证

已在项目外的临时 Hugo 0.110.0 小站验证：

1. 顶层 front matter 自定义 shelf 数组可通过 `.Params.shelf` 读取。
2. `layouts/shortcodes/shelf.html` 可按 ID 从所属文章读取记录并渲染锚点。
3. 使用 `newScratch`、`SetInMap` 和 `merge` 聚合；两篇周记提及同一论文只产生一个条目，并保留两条回链。
4. 新增一本书后，汇总输出两种类型、两个唯一条目，完全在 Hugo 构建期完成。

这是数据路线可行性证明，不是已发布功能；正式实现仍需补齐校验、分类界面、去重冲突处理及历史内容确认。
